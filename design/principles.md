# 設計原則

本檔是整個系統的憲法。其他檔案與此衝突時,以此為準;雲端 session 填表時,違反此檔即為錯誤。

## 1. 天生的是屬性,練出來的是技能

- 屬性:七項,4d6 生成,終身不練。
- 技能:三屬性加總為底值,靠經驗升級,從 0 起。
- 池子同理:天生池 = 屬性加總(人人有);練成池 = 技能(凡人沒有)。
- 判準:能靠練習改變的,就不是屬性。反應、感知、儀容都是技能(儀容 = 化妝/儀態)。
- 屬性要不要拆,看副技能層需不需要那個區分。手與腳在副技能層分道,所以 Ski/Agi 拆;相貌與氣場分不開,所以不拆。

## 2. 沒有職業,只有技能

- 「劍客」「法師」是對使用紀錄的事後描述,不是事前選擇。
- 起手包是借款不是指令:前三場起手技能的經驗可無損挪動,三場後鎖定。
- 練成煉金術士的法師不是跑偏,是系統正確運作。

## 3. 所有數字都是「點」,不是「比例」

- 系統中一切 % 皆指百分點。「削減難度 20%」= 75 → 55,永遠不是 75 → 60。
- 規則書第一頁與 DM 提示詞第一條都要明寫。

## 4. 一條數線

- 對抗、難度判定、防禦鏈、溢出、致命,全部在同一條「幅度」數線上運算。
- 解算器只有一個核心函數。任何新機制若需要第二條數線,先懷疑它。

## 5. 能用數字擋的,不用規則擋

- 外科手術不需要「未受訓不可」旗標:難度階高、底值 42、沒副技能,DM 丟 75,玩家自己不會試。
- `untrained: 不可` 清單極短,只收「零就是零」的技能(語言、讀寫)。

## 6. 命名給人讀,也給模型讀

- 魔法來源用「內源 / 外源」,不用「黑 / 白」——模型一定讀成善惡。
- 能源條用通行讀法:精 = 體力、氣 = 內力、神 = 神識。
- 任何「有的是 A、有的是 B」的規則都要改寫成「依 X 決定」。模型最怕「有的是」。

## 7. 填表不下判斷(給雲端 session)

- 只填 schema 欄位。禁止自創數值、禁止加機制、禁止抄既有系統的敘述文字。
- 副技能總效果 ≤ 難度階預算(見 skill-schema)。
- 發現規則沒講清楚的地方,寫進 `ambiguities.md`,不要自行裁決。

## 8. 別變成大記帳

- 記帳交給解算器與使用紀錄,人只看結算。
- 任何機制若需要玩家手算超過一次加減,先懷疑它。

## 9. 下限低是常態

- Power player 配 Power DM,任何系統下限都低。機制只管算得對;彈性與合理度留給桌子。
- 模型 DM 沒有「別太噁心人」的分寸,所以給它的規則必須是機械的:非戰鬥經驗只來自有後果的判定、場末自動標記未使用技能、疊加走白名單。
